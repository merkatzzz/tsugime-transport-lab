# 建築・搬送独立実験 検証報告

検証日：2026年11月9日。対象は本納品の独立プロトタイプのみ。既存本編には統合していません。

## 検証済みの範囲

8搬送体・15基本チャンク、2生活階、固定EV1系統、A/B/Cの固定計画を対象にしました。1チャンクの外形は8×8×5mです。搬送体内の恒久連結と、搬送体同士の取り外し可能な境界を分離しています。

`npm test`：24テスト成功。開口の両側の実壁、身体半径0.35m、床支持、扉、家具を用いた通過試験、0.25m格子での実幾何の到達範囲探索、搬送の連続衝突判定、0.25秒間隔での補助占有検査、全8搬送体の乗員位置保持、固定乗員保持、通常退避・入場制限・孤立・再接続・EV・デバッグ復帰を検証しました。

| --- | ---: | ---: | ---: | ---: | ---: |
| A→B | 30 | 1200 | 0 | 4体 | 82秒 |
| B→C | 32 | 1236 | 0 | 4体 | 84秒 |
| C→A | 30 | 1200 | 0 | 4体 | 82秒 |

時間には5秒の退避警告と約2.8秒のシャッター・固定工程を含みません。各検査は同一搬送体内の継ぎ目を衝突と数えず、他搬送体との各基本チャンク外形、固定回廊・EV・固定観察室に対して行います。平面上の接触は非貫入として許可します。各生活階で隣り合う外形間に機械的な余裕は設けていないため、実寸機械の公差検証は未実施です。

静的開口グラフだけでは成功扱いにせず、両側の壁を含む身体通過試験で一致を確認しました。BのR4には0.4mの見通しが残り、細い視線は通る一方、身体は通れません。施錠されたR2の2号室と観察窓付き3号室には幾何探索でも入れません。シャッター閉鎖中はライブ接続グラフも遮断されます。

## 配置の意味

- **A**：第三層のR1・R2、第二層のR3・R4が固定EVを介して連続。広間H1は第三層、L字集会室L1は第二層。8/8搬送体へ到達可能。東端の固定観察室はL1の側壁で遮断され、到達不能。
- **B**：R1が東寄りへ移り、R2は第二層の店舗T1へ側面で接続。T2とL1は第三層に集合。R4は第二層の狭い固定開口に到着し、視認のみ・孤立。7/8搬送体へ到達可能。第二層のH1東口が固定観察室につながり、Aで入れなかった場所へ新たに到達。
- **C**：R2・R4とT1・L1が第三層へ、R1・R3とT2・H1が第二層へ再集合。R4は広い開口で再接続。A・Bのどちらとも異なり、8/8搬送体へ到達可能。

この「到達」は搬送体への到達です。建築内の非公開居室まで全て進入可能という意味ではありません。

## 孤立・退避方式の比較

| 方式 | 実装・検証 | 分かったこと |
| --- | --- | --- |
| 警告のみ | 5秒の事前警告を表示 | 在室者が残るため、単独では閉じ込めを防げない |
| 警告＋新規入場制限 | 通常モードで実装 | 閉鎖準備中にR4へ新たに入る操作を拒否。退出は許可 |
| 在室・継ぎ目の退避待ち | 通常モードで実装 | 搬送を止め、歩いて回廊へ戻るまでシャッターを閉じない。物理的な退避を保証 |
| 意図的な孤立＋次周期 | 実験モードで実装 | R4内に同乗→Bで孤立→次のCで物理再接続。通常モードと明示的に分離 |
| 別の常設物理経路 | 未実装 | 孤立の実験条件を壊すため、今回は代替通路を追加していない |
| 特別な救助搬送体 | 未実装 | 救助車両の退避・ドック・乗換経路まで検証が必要 |
| デバッグ復帰 | 明示ボタンを実装 | 試遊の継続には有効。通常出口や安全な建築計画の根拠には含めない |

実験モードの周期開始ボタンは全域から操作できる開発用制御です。本編で孤立した住人が周期をどう要求するか、停電時の救出、通信設備の有無は今回決定していません。

## 依頼の7問への回答

1. **同一外形の中での自由度**：1セルに個室と偏心廊下、3つの簡易部屋と廊下、厚い未使用構造帯を同居させました。2セルの幅広店舗・奥行き店舗、3セルL字集会室、4セル高天井広間も成立しています。自由度は内部壁と開口を設計する範囲で大きい一方、共通外形を越える張出しや段差、他搬送体をまたぐ固定家具は採用していません。
2. **3配置を実搬送で循環できたか**：A→B→C→Aの全直線区間を検査し、搬送体と乗員の連続座標を使って到着させています。途中を飛ばす配置交換はありません。退避ベイ2列と横行路を用意することが成立条件です。
3. **同時移動の範囲**：同じ生活階の4搬送体が、互いに重ならないX帯で同時昇降・同時Z移動できます。異なる横行先へ復帰する工程は1体ずつです。全8体の同時運転や、任意形状のすれ違いは証明していません。
4. **非対称開口・幅違いの接続**：居室側の偏心開口、広い固定回廊開口、1.5mの細廊下、幅広売場通路を接続しました。両側の重なりを判定し、0.4mの隙間は通行不可としました。45度区間はL1内部の平行な斜め壁で表現し、チャンク格子はずらしていません。
5. **地図と3D通行の一致**：地図とThree.js描画は同じ建築・壁・開口データを参照し、静的グラフと身体通過試験・床上の幾何到達探索は一致しました。固定観察室はAで未到達、B・Cで到達することも実幾何探索で確認しました。ブラウザによる見え方と入力の確認は下記記録で分離します。
6. **孤立時の問題と有効な方式**：警告だけでは在室者を保護できません。在室・継ぎ目の退避待ちと新規入場制限の組合せが通常モードに有効でした。固定観察室もC→Aで孤立するため同じ退避保護を適用し、B→C中はその室内の乗員が固定座標に残ることを検証しました。意図的孤立では次周期の再接続が実在する経路になります。ただし次周期を起動できない事故では出口がなく、別の救助計画が必要です。
7. **大規模化の障害**：退避ベイの面積、横行路の混雑、搬送順序の探索、同時運転の予約、複雑な外形の掃引、機械公差、EVへの経路、内部の細かい通行グラフが主な課題です。本実装の幾何探索は検証用の小規模格子であり、大規模施設向けの階層化したナビゲーションではありません。

## 実メッシュ検証と視覚確認の記録

実際のThree.jsメッシュ生成・変換もCPUで検査しました。壁厚・見切り・全シャッターの開放／中間／閉鎖を含め、全外形内に収まることを確認しました。固定回廊の壁とシャッターもZ≤0に収め、搬送域への張出しを拒否します。目の高さの実メッシュへのレイ判定でBの0.4m隙間からの視認と、隣の不透明壁での遮断を確認しました。GPU描画器と文字テクスチャだけを代替した検査であり、実ブラウザの描画確認ではありません。

ローカル管理プレビューは `relay could not open browser port 4173: timed out waiting for relay readiness` により開始できませんでした。本人限定のSites配置には成功しましたが、共有ChromeのURL移動・確認タブ作成は `Browser Use could not read requirements` で失敗しました。アドレス入力の代替操作でもページはabout:blankのままでした。したがってWebGL初期化、画面の見え方、実ブラウザ入力、スマートフォン実機の試遊は未確認です。ブラウザ側の記録は `docs/evidence/browser-results.json` に保存しています。スクリーンショットは実3D表示を確認できなかったため添付していません。幾何・ロジックの24テストを、描画確認の代わりには扱いません。

## 未解決の制約

- 運動学的プロトタイプであり、重量・荷重・慣性・制動距離・振動・構造強度を扱いません。理想ガントリーの車台や掴み機構の詳細は省略しています。
- 設備継手、給排水・換気、避難法規、防火区画、停電や駆動故障を検証していません。
- 全外形の非貫入を保証する設計ですが、隣接ドックの寸法公差と着床ブリッジの製作可能性は未検証です。
- 内部は水平床のみ。身体は円柱断面で、階段、屈み、高さを変えた細隙通過は扱いません。
- プレイヤー1人、固定EV1系統。多人数・複数EVの競合、NPC退避は未実装です。
- 計画A/B/Cとその経路は手設計です。任意配置の自動再構成や施設全体の搬送成立を証明しません。
- ブラウザのメモリとGPUに依存する簡素なモデルです。スマートフォン実機の継続動作・操作感は未検証です。
