## 操作

通常は従来のABC運用。画面の「開発実験：故障後の屋根・落下探索」を開き、「故障実験：A→B中間停止」を押す。通常状態をメモリに退避してから、検証済みの停止配置を再現する。任意の周期・任意のプレイヤー位置で故障を発生させる汎用イベントではない。

- 開始位置は既存のSM0室内。X46/Y0/Z62.4、東向き。屋根から開始しない。
- WASD、Shift、既存の視点操作はそのまま使う。SM0東シャッターから東へ歩くとSM1屋根へ出る。ジャンプは追加しない。
- 「上昇」「下降」は押している間だけ上下2m/s。指・マウスを離す／キャンセル／画面からフォーカスを失うと入力を止める。開発上下モードはその場で保持する。
- 「通常歩行に戻る」で重力を再開する。空中なら落下する。壁・床内では切替を拒否する。
- 室内で上昇すれば天井に当たる。高い屋根を試す際は、先に東口から屋根へ出る。上下操作でも建築を貫通させない。
- 「安全位置に復帰」は開発専用の明示操作で、試験開始室内へ戻す。既存のデバッグ復帰も故障中はこちらへ接続する。死亡・救助イベントや自動ワープは追加しない。
- 「通常状態へ戻す」で故障前の周期、プレイヤーの建築内座標、生活・所持品、通常扉、速度、自動搬送設定と表示モードを復元する。

故障中は通常搬送、EV、通常の保存・読込を操作不可にする。通常セーブの形式と保存キーは変更せず、故障データで上書きしない。故障状態の永続保存は今回未対応。Eキーによる上下操作は追加しない。

## 停止配置と通常運転の保全

[正常A配置](evidence/stage15-before.svg) ／ [故障停止配置](evidence/stage15-stop.svg) ／ [全停止位置・搬送予約・検査・歩行軌跡](evidence/stage15-scenario.json)。

既存のA→B協調搬送を複製し、故障試験内だけSM1の出発を2.3秒遅らせる。経路・向き・目標は変更しない。時刻4.3秒で `positionDuring` の実座標を固定する。通常の18搬送計画と建築定義は元のまま。全経路の連続掃引・0.2m余裕・回転包絡・固定設備・複数体予約を再検証する。[正常定義のSHA256保全](evidence/stage15-normal-preserved.json) に元コミットとの差がないことを記録する。

移動対象34体のうち、完了7体、未出発9体、途中18体。別に、この遷移で通常待機する建築・固定建築32体。途中の一体搬送体も一つの剛体姿勢を使い、セル間の相対位置は変更しない。回転角と上下位置を含む全66体の姿勢はJSONを正本とする。

| 対象 | 停止状態と使い方 |
| --- | --- |
| SM0 | X42/Y0/Z58.4の既存室内。床上面+0.16m。東口だけ故障開放 |

通常の自動退避規則は変更していない。SM0型の退避修復も維持する。今回だけはボタンで明示した試験開始状態へ切り替え、正常搬送の警告・退避・開閉・移動処理とは別に探索する。

## シャッターと最初の屋根

[出口の模式断面](evidence/stage15-exit-section.svg)。SM0:Eのみを通常の接続判定・搬送中の閉鎖量から独立して開く。ほかの搬送シャッターと分割壁は閉鎖状態を保つ。停止位置がAの完成配置と異なるため、通常のA接続から床継手を作らない。実際に位置が変わっていない恒久接続7本だけは既存の継手を維持する。

SM0東外形端X50とSM1屋根端X50.4の間は0.4mの空隙。新たな橋や床は追加していない。床上面+0.16mから屋根上面0.00mへは16cm低くなる。通常歩行で空隙を越える間に短く落下し、SM1の実屋根へ着地する。停止時刻の調整により、初回から大きな落下や開発上昇を必要としない。

室内の視点X46/Y1.81/Z62.4から屋根中央X54.4/Y0/Z62.4へ向けた実三角形のレイ検査でも、最初の可視面がSM1の屋根になることを確認する。開いた見た目と安全な足場は別に扱い、選択したシャッターにも架空の通路床は付けない。

## 共通の屋根・空間衝突

`fault-geometry.js` は本番Viewの建築生成・姿勢・シャッター状態・露出面処理を再利用する。WebGLレンダラーを作らずに同じメッシュを構築し、表示される実三角形を取り出す。文字注釈、水面と流水の装飾は衝突対象外。透明な実手すり・ガラスは除外しない。床・壁・屋根・階段・収納部材・外殻底床も同じ検査対象にする。

`fault-physics.js` は三角形を4mの三次元格子で索引化し、高さ1.70m・半径0.35mの垂直カプセルで身体全体を検査する。支持座標Yは従来どおり見える足裏より0.16m下。カメラはY+1.81mで、頭頂の判定Y+1.86mより下に収める。屋根を外接矩形で一律に塞がず、L字の欠け、回転姿勢、実際の吹き抜け開口を保つ。

水平移動は最大0.06m、上下移動は最大0.04mに分割し、接触時は境界を二分探索する。重力は1/120秒単位で処理し、9.81m/s²、下降速度上限55m/sを試作値とする。死亡・ダメージ・転倒アニメーションは追加しない。屋根端の透明な防壁も追加しない。

故障中は位置だけでなく時計・NPC・設備・扉・開閉機構も固定し、作成した衝突形状と表示を一致させる。通常のEによる扉・設備操作はこの初版では行わない。通常へ戻せば従来の操作に復帰する。屋根や床を後から動かす故障の再開・回復処理は未実装。

## 落下と上下操作の結果

[屋根移動後の実位置](evidence/stage15-roof-route.svg) ／ [入力再生の落下軌跡](evidence/stage15-fall-profile.svg)。

- SM0室内から通常入力でSM1屋根へ着地。支持座標は約−0.16m、見える足裏は0m。
- SM1北端から踏み外し、下のBR3屋根へ着地。支持座標は約−6.96m、見える足裏は−6.8m。室内床へ屋根を貫通して落ちない。
- 開発上昇は外殻天井で身体全体が止まり、下降は屋根で止まる。通常歩行へ戻すと重力と支持判定が再開する。
- 開いたB三段吹き抜けの実メッシュを使う別検査では、中間二段の開口を通過し、最下段の本当の床へ着地する。当たり判定だけの塞ぎ面を作らない。
- 実床がない検査では、有限の座標を保って落下し続け、明示した安全復帰で再試行できる。試験施設には既存の外殻底床があり、その上へ落ちればそこで着地する。新しい全面床は追加していない。

## 検証と限界

[最終の自動検証](evidence/stage15-verification.json) ／ [全テスト](evidence/stage15-tests.txt) ／ [図面XML](evidence/stage15-drawing-xml.txt) ／ [実画面の障害記録](evidence/stage15-browser.json)。全体回帰260/260が成功。最後の故障専用の支持判定・操作固定・範囲復元も[重点9件](evidence/stage15-final-focused-tests.txt)で9/9成功した（全体実行と重複するため件数は合算しない）。正常の面処理24条件、接続部6条件、5図面のXML検査も成功。最終件数と終了コードはこれらを正本とする。実施していないWebGL検証を成功と扱わない。

屋根支持・落下、姿勢と機構の固定、正常C状態への復元、通常保存の保護、PC/タッチの上下ボタン、入力キャンセル、回転L字屋根、通常ABC・SM0退避・吹き抜け・大部屋・EV・シャッター・地図・生活・保存を検査する。通常計画を再探索する代わりに、保全済み18経路の同一性と連続離隔を再検証する。

残件は実WebGLの視界・操作感、PC/スマホの画面占有、長時間の性能、段差・縁や複雑な斜面の接触感。格子索引とカプセルは最初の共通実装であり、将来の全建築・全操作についての完成保証ではない。危険な開口を試すときは安全復帰を使う。

## A側試験区域と次回

今回は増設を保留。必須の室内→屋根、上下・落下・正常復帰に集中し、A側の居住設定や秘密を確定していない。次回は、停止配置JSONと屋根支持検査を使って1〜3セルの候補を選び、通常18経路との離隔、故障時だけの到達路、頭上空間を検査する必要がある。空欄だから安全と決めつけない。支持装置・非接触搬送の原理・昇降アーム・新NPCは追加しない。

再開はstage15-development。Node 22以上、Python 3。`npm start`、`npm test`、`npm run verify`。ビルド・依存追加なし。図面は `npm run evidence`、配布は `npm run package`。同梱ソースZIPだけでも検証できるよう、正常定義の比較には保全したSHA256一覧を使い、Gitの作業履歴を必須にしない。

主なファイル：fault-scenario.js（時間予約と停止時刻）、fault-experiment.js（開始・正常復帰）、fault-geometry.js（本番形状）、fault-physics.js（屋根・カプセル・重力）、fault-controls.js（開発操作）、fault-map.js（実座標地図）。既存Simulation/Viewへは故障中だけの分岐を加える。

最新版ZIPはサイトの `downloads/tsugime-lab-source.zip`。報告は `report.html`。閲覧権限は既存の設定を維持する。
