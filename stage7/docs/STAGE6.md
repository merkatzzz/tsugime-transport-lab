## 3. 遠隔区域への往復と安全性

通常区域とD1〜D4の間に、どの安定配置でも歩行グラフの接続はありません。S1に乗り、上部搬送空間を実移動して渡ります。

代表経路：A→BはS1の(42,12.8,8.4)→(42,6.4,8.4)→(92.4,6.4,8.4)→(92.4,12.8,8.4)。B→Cで逆に戻り、C→AではS1は通常区域に留まります。実際の協調搬送は他体の区間境界で細分化されますが、すべて連続した軸移動です。全区間の位置・角度・所要時間は`stage6-service-routes.json`に出力しています。

「徒歩でEVから到達可能」と「往復搬送サービスで安全」を別の集合として扱います。`reachable`は徒歩のみで、D1〜D4を一切追加しません。`serviceReachable`は、BでS1がD1へ実接続し、次のCでS1が通常区域へ戻れる場合だけ、その便とつながる遠隔区画を安全集合へ含めます。搬送計画自体も開始前に衝突検証します。通常訪問を残留例外フラグにする処理ではありません。

B→Cでは遠隔区画は安全集合から外れ、滞在者へ警告。本人がS1へ戻らなければ、身体幅・床支持・壁・家具を満たす実経路を探索し、既存の身体コントローラでS1へ移動してから帰還します。D4からの実退避は約22.34mの検証経路です。戻れなければ明示的な安全停止であり、座標ワープはしません。

## 4. 固定泉と新型生物

5基の泉は生活床の外周に設けた専用の固定骨格ポケットです。移動用の空欄・着床セルとしては扱わず、地図の空欄候補から除外しています。固定障害物として全搬送掃引を検査。住人用の床支持はなく、全高の密閉貯留槽の一面にだけ生物用の低い開口があります。

| 泉 | 固定位置X/Y/Z | 接続できる面 | 接続個体 |
| --- | --- | --- | --- |
| P1 | 25.2 / −12.8 / 10.9 | 西面のみ | BN1 / N1 |
| P2 | 67.2 / 0 / 19.3 | 西面のみ | BN2 / N2 |
| P3 | 58.8 / 12.8 / 19.3 | 西面のみ | BN3 / N3 |
| PA | 67.2 / 12.8 / 2.5 | 西面のみ | BN4 / N4、A/C |
| PB | 61.3 / 0 / 8.4 | 北面のみ | BN4 / N4、B |

貯留槽は各3×3×6m。PA/PBは単なる泉IDで、A側旧型生物の領域を実装したものではありません。泉の由来・施設の正体は決めていません。

BN1〜BN4は壁に固着する非人間型の生体機械。単体移動・持ち運び・敵AI・攻撃はありません。本体、供給器官、触手は別の3D形状です。N4が回れば寄生壁・本体・器官・開口も同じ親座標で回ります。主人公は供給器官に近づきEで利用でき、毒性が残る間は供給を拒否します。本編の所持品・経済・生存値とは未統合です。

着床・整列→設備シャッター開放→触手伸長→液面に接触→泉全体の中和→供給、の順です。搬送警告で触手を引き戻し、設備口を閉鎖。触手と口の収納完了を待つ`retracting`状態を設け、未収納のまま移動・回転へ進めません。

N1/N3/N4は隣接接続。N2は外壁から泉口まで8.8mで、8mの空欄と両端離隔をまたぐ一直線接続です。触手の最大長は12m。人工伸縮管ではなく、有機的な本体から伸びる曲線チューブ形状を使います。経路全長を予約し、動体が動く前に全個体を収納します。

接続は階・向き・中心整列・実開口・長さ・寄生壁側の閉塞・他チャンク・別貯留槽・同時占有を確認。失敗理由を検証パネルへ表示します。予約は泉ごとに一個体だけです。正しい向きでも途中に別チャンクがあれば接続できません。

安定着床後、開放・伸長・中和を待った個体数：

| 周期 | 第一層 | 第二層 | 第三層 |
| --- | --- | --- | --- |
| A/C | 1 | 1 | 2 |
| B | 1 | 2 | 1 |

「接続数」と「供給可能数」は別表示。着床直後は伸長と中和待ちのため供給可能数が一時的に少なくなります。

泉は独立した連続毒性値を持ち、毒性流入は常時+0.025/秒、接続個体の中和能力は−0.12/秒。全体が回復できる余剰能力があります。0.2以下で利用可能、解除すると再上昇します。数値は試験用で、通常画面では割合や流量を見せません。初期状態からおおむね十秒以内に利用できる仮設定です。液体の発生源や流体化学を確定したものではありません。

新型が離れた着床位置は再利用可能です。特にN4のPA側・PB側への再着床経路を実搬送で検証しています。将来の旧型用に接続位置と退避空間を残していますが、旧型本体・秘密区域・イベント・会話は今回追加していません。

## 5. 90度回転と座標系

N4は一度上部デッキへ降り、回転ベイ(75.6,6.4,25.2)へ移動。中心(79.6,6.4,29.2)の周囲で0→90度、B→Cは90→0度を補間し、別階へ運びます。1倍速の90度回転は3秒です。H1/H2など大型搬送体は回転させません。

8m正方形の全円掃引半径は約5.657m。離隔込み直径約11.714mを確保し、全角度の円掃引を包む保守的AABBで他体・固定設備との連続相対掃引を検査します。端点だけ、あるいは角度サンプリングだけで安全と判定していません。メッシュの15度刻み検査はその補助です。

`pose.js`に局所→世界、世界→局所、壁線、矩形、面方向、Three.js親グループの変換を集約。プレイヤーも同じ局所位置で移動し、身体に随伴する向きだけを連続回転させます。無関係な方向へのカメラジャンプはありません。移動完了時の角度は目標値0/90度に一致し、前周期への加算による誤差は蓄積しません。

開口の面方向と区間の反転、扉・家具・生物の当たり判定、地図の親回転も同じ変換を使用。N4のローカル南口はBで西向きになり、U3東口へ実接続します。ローカル東の生物口はBで南向きになり、PB北面へ接続します。

## 6. 演出・EV・主要ファイル

入室は初期0.14秒。退出も同じ柔らかい中央拡大型の明転とし、初期0.12秒、入室設定に追随して0.10〜0.16秒です。従来の退出用一様暗幕は使用しません。退出位置・視線、会話と訪問の分離、OSの動きを減らす設定を維持。

## 7. 検証と限界

現行の全テストと保存版1〜5を`npm run verify`で実行。計画18案は全て成立。既存の保持前進、H1/H2同乗・分離、C0保管・近道、三層上下搬送、孤立例外、NPC・個室・環境音状態も回帰試験します。

各周期の全供給室へ、同じ階の固定EV乗場から実歩行する12経路もコントローラで再生しています。

新規では遠隔徒歩非接続・往復・実退避、回転時の相対位置と視線、途中だけ接触する反例、触手の方向・長さ・障害物・実開口・排他、毒性上昇と再中和、供給拒否、9遷移反復、実メッシュの液面接触と遮蔽を検証。経路が成立しない場合の安全停止は維持しています。

管理プレビューは今回も`relay could not open browser port 4173: timed out waiting for relay readiness`で失敗し、`sites-preview status`は停止でした。共有ブラウザの起動・存在は確認できましたが、アプリ画面へ到達できていません。別サーバー／別ブラウザ経路で迂回していません。

したがって、実WebGLの外観、視点移動のチラつき、操作の自然さ、触手の見やすさ、明転の視覚的な自然さ、音量・ミュートの聴感は未確認です。CPU上のThree.js形状と制御試験を、実画面確認として報告しません。

残る制約は、同階の実経路で行う自動退避（EVを使った階またぎ自動退避は未実装）、固定された今回のA/B/C計画に対する往復サービスの定義、研究用の簡易形状・中和速度です。任意の施設や任意の回転経路を自動生成できる機構ではありません。
